# YOUKAI 联网更新

仓库：[erbaiqi-pro/YOUKAI](https://github.com/erbaiqi-pro/YOUKAI)。当前产品为 **1.0.0 正式版**，内置26个工具，无导出PDF，分类不变。

## 用户如何更新

1. 打开YOUKAI，后台发现新版本后只在网站LOGO旁显示红色NEW，没有更新弹窗。
2. 点击NEW查看更新；也可在系统设置中点“检查更新”，立即查询。
3. 小更新点“更新脚本”，完成后点“重新加载”。原有路径、个人表格、收藏和自定义脚本保留。
4. 大版本显示“前往官网下载”，不下载或覆盖当前插件，用户自行安装完整安装包。

第一次从测试版转为正式版，会同步升级更新器。旧面板可能显示内部编号1.0.3；重新加载后显示1.0.0正式版。请先停止脚本和批处理任务，再进行更新。

自动检查有6小时缓存。要立即测试本次通知，请点系统设置里的“检查更新”。GitHub真实限流时仍需等待冷却，不会因连续点击而重复发送请求。

## 两种日常更新

| 更新 | 范围 | 路径设置 |
| --- | --- | --- |
| 同一1.0.x系列的脚本更新 | 内置JSX、对应说明、CSV模板及版本清单 | 原样保留 |
| 1.1.0、2.0.0等版本，或引擎有变 | 跳转作者网站，手动获取完整安装包 | 不会被在线检查改动；运行完整安装器沿用备份与清理流程 |

脚本更新包不能携带HTML、CSS、面板JS、宿主桥接、config.json、安装标记或其他个人文件。新增文件与个人文件重名时停止更新。更新前保留完整旧目录，逐文件校验，失败回滚，并支持中断恢复。未来脚本更新包只含脚本配套文件；客户端依据完整目标清单增补、替换或移除官方脚本，未知的个人脚本保留，跳过中间版本也可更新。

## 本次版本编号

对外名称、安装包名称和package.json版本为1.0.0，channel为stable。

`release.json.version`、CEP版本和GitHub tag采用兼容编号1.0.3；`productVersion`为1.0.0，`engineVersion`为1.0.3。旧测试版1.0.1／1.0.2只比较数字，无法直接识别数值更小的1.0.0，因此保留独立递增编号。历史v1.0.0测试发布与提交不改写。正式发布名称仍为“YOUKAI 1.0.0 正式版”。

未来发布同时递增内部更新编号；1.0.1脚本版可使用内部编号1.0.4。面板始终显示productVersion。引擎不变时engineVersion和CEP版本保持不变；引擎改变时用完整安装包。

## 构建与发布

1. 修改唯一开发目录；保持9个已验收脚本和集体注释的原始运行代码保护规则。
2. 更新release.json：内部version递增，productVersion填写展示版本，engineVersion填写所需引擎版本，核对scriptCount；同步package.json的产品版本。
3. `npm test`和`npm run test:ui`通过后，`python tools/build-release.py`生成安装包及开源副本。
4. 日常脚本更新用`python tools/build-update.py`，默认`--kind scripts`。大版本用`--kind installer`，仅生成提示清单。客户端会把跨主/次版本或引擎不匹配的脚本包也转为官网下载。
5. 仅本次使用`--kind bootstrap`生成完整迁移ZIP，供旧更新器升级到第2代；构建器限制此类型只用于内部1.0.3、产品1.0.0。
6. 将干净源码提交GitHub，按内部编号创建正式Release，名称填写产品版本。附件为安装包、YOUKAI-Update.json、对应ZIP（若有）、安装说明及SHA256SUMS.txt。设为latest并关闭prerelease。
7. 匿名下载核对哈希，使用旧测试版更新器在隔离CEP目录验证发现更新和升级。不要替用户直接更新正在使用的测试插件，留给用户验证NEW通知。

客户端通过GitHub的公开latest/download清单检查，不需要API Key或私人令牌。个人CSV、工作稿、测试记录和密钥不进入安装包、更新包或公开源码。
